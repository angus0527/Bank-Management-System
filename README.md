# Bank-Management-System

## 快速开始（第 2 周保底演示）

环境：C++17，无需 Qt（核心层与控制台入口不依赖界面）。

```bash
# 方式一：CMake（CLion 直接打开工程即可）
cmake -B build && cmake --build build && ./build/BankManage

# 方式二：直接用 g++（Windows MinGW 示例，-static 免运行库 DLL 依赖）
g++ -std=c++17 -static -Iinclude console_main.cpp src/*.cpp -o build/BankManage.exe
```

运行 `console_main` 将演示第 2 周里程碑全流程：登录 → 开户 → 存款 → 取款 →
转账 → 异常提示（余额不足 / 金额非法 / 账户不存在 / 账户冻结）→ 活期结息 →
存盘 → 重开读档验证数据完好。运行时数据写入 `data/`（已被 .gitignore 排除）。

## 二、技术方案与设计约定

- **C++17 + Qt 6**（Qt Creator，两人统一同一版本、同一编译器）+ **纯文件存储** + git。
- **分层架构，core 层不依赖 Qt**：

```
ui 层（Qt 界面）        只调用 Bank 的公共接口
storage 层（文件读写）  Storage / Logger
core 层（领域逻辑）     Account 体系 / User 体系 / Transaction / Bank / 异常体系
```

好处：① 类体系有多个继承层次可讲（报告与答辩的主要得分点）；② Qt 进度万一失控，core + 临时控制台入口就是可演示的保底版本（第 2 周末即可达成）。

**必须遵守的设计约定（第 1 周定死，避免后期返工）：**

1. 金额一律用 `long long` 存"**分**"（如 123.45 元 → 12345），显示时再转字符串。避免 double 精度问题——这也是答辩常问点。
2. 日期自己实现一个 `Date` 类（年月日、日期加减、天数差、格式化），不用第三方库；这是报告可写的加分点。
3. 所有业务入口集中在 `Bank` 类，UI 不直接碰 Account/User 的内部字段。
4. 错误一律用自定义异常抛出（`throw BankException 及子类`），UI 层 catch 后弹窗提示，不允许用返回值 -1 之类约定。
5. 密码可以简单混淆存储（如异或/位运算），报告里如实说明安全性局限与改进方向即可。

## 四、类体系清单（可直接照此画 UML 类图）

### 4.1 core 层

| 类 | 类型 | 职责 | 关键成员 / 方法 |
|---|---|---|---|
| `Account` | 抽象基类 | 账户公共属性与操作 | `id, ownerId, balance(分), openDate, frozen`；虚函数 `calcInterest()`, `type()`, `withdraw()`, `deposit()`；**虚析构** |
| `CurrentAccount` | 继承 Account | 活期 | 年利率；按日计息 |
| `FixedAccount` | 继承 Account | 定期（第 4 周） | 期限(月)、到期日、自动转存标志；提前支取按活期 |
| `CreditAccount` | 继承 Account | 信用（第 4 周） | 信用额度、欠款、日利率；还款 |
| `User` | 基类 | 用户公共信息 | `id, name, password`；虚函数 `role()` |
| `Customer` | 继承 User | 客户 | 电话、名下账户 id 列表 |
| `Admin` | 继承 User | 管理员 | （标记角色即可） |
| `Transaction` | 类（可做基类） | 一条交易流水 | `id, 时间, 类型, 金额, 对方账户, 余额快照`；加分：派生 Deposit/Withdraw/Transfer 子类重写 `describe()` |
| `Bank` | 管理类（门面） | 全部业务入口 | `map<long long, unique_ptr<Account>>`、用户表、流水表；`openAccount/deposit/withdraw/transfer/query/settleInterest/login...` |
| `BankException` | 异常基类 | 统一异常 | 继承 `std::exception`；子类：`InsufficientBalance / AccountNotFound / AccountFrozen / InvalidAmount / AuthFail` |
| `Date` | 工具类 | 日期处理 | 年月日、天数差、日期加月/日、格式化、当前日期 |

### 4.2 storage 层

| 类 | 职责 |
|---|---|
| `Storage`（抽象接口） | `load(Bank&)` / `save(Bank&)`；加分点：抽象接口便于以后换数据库 |
| `TextFileStorage` | 实现三个文本文件的读写 |
| `Logger` | 操作日志追加写入（独立文件） |

### 4.3 ui 层（Qt，每人为自己的模块写界面）

`LoginDialog`、`MainWindow`（客户视图 / 管理员视图两套导航）、`OpenAccountDialog`、`DepositWithdrawDialog`、`TransferDialog`、`TransactionQueryDialog`（A）、`FixedAccountDialog` / `CreditDialog`（A）、`AdminPanel`（冻结/利率/日志，B）、`StatsDialog`（图表/导出，B）。

继承层次共 4 处：**账户体系（多态计息）、用户体系、异常体系、（可选）流水体系**——报告"系统设计"章按此组织。

## 五、数据文件格式设计（storage 层实现依据）

目录 `data/`，纯文本，`|` 分隔（输入端校验字段中不得出现 `|` 和换行）。

**users.txt**（每行一个用户）
```
U|用户id|角色(C或A)|姓名|混淆后密码|电话
U|10001|A|admin|aX9f|0000
U|20001|C|张三|k3Pq|13800000000
```

**accounts.txt**（每行一个账户，公共字段在前，各类型附加字段在后）
```
A|账号|类型(C活期/F定期/X信用)|用户id|余额(分)|开户日期|年利率x10000|期限月|到期日|自动转存0/1|信用额度(分)|欠款(分)
A|62001|C|20001|123450|2026-10-26|35|0|0|0|0|0|2026-10-26
A|62002|F|20001|1000000|2026-11-10|175|12|2027-11-10|1|0|0
```

> 活期(C)账户在第 12 个公共字段后附加**第 13 字段"上次结息日"**（按日计息的起算点，
> [contract] 变更：2026-10-29 由 A 补充；老数据无此字段时读档方默认取开户日，向后兼容）。
> 交易类型码为英文 `DEP/WDR/TRF/INT`（见 transactions.txt 示例）。

**transactions.txt**（每行一条流水）
```
T|流水号|时间|类型(DEP/WDR/TRF/INT)|付款账号|收款账号|金额(分)|余额快照(分)|备注
T|1|2026-10-26 14:30:05|DEP|0|62001|50000|173450|开户存入
```

**logs.txt**（操作日志，B 的扩展用）
```
[2026-10-26 14:31:00] admin(10001) 开户 62001 (客户 20001)
```
