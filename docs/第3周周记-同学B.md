1. **图形客户端主框架与双视图构建（`MainWindow`）**：
   - 继承 `QMainWindow`，通过 `QStackedWidget` 实现“普通储户网银视图”与“系统管理员控制台视图”的动态权限隔离；
   - 储户视图设计了顶部客户信息横幅、多账号下拉联动选择卡片、大号余额醒目展示（元）、以及底部历史交易流水表格（采用 `QTableWidget` 实现按交易类型即时下拉过滤）；

2. **业务对话框全套落地与异常拦截对接**：
   - 独立设计了存取款窗口 `DepositWithdrawDialog`、转账窗口 `TransferDialog` 与开户申请窗口 `OpenAccountDialog`；
   - 严格坚守架构解耦规范，界面层严禁直接操作底层数据结构，统一经由 `Bank` 门面调用，通过 `try ... catch (const BankException &e)` 统一截获核心层异常并弹出友好的 `QMessageBox` 警示，界面无崩溃、无状态残留；
   - 实现了对账单导出功能，支持将单账户历史流水导出为标准 CSV 文件，并写入 UTF-8 BOM 确保 Microsoft Excel 打开不乱码。
3. **构建流程自动化优化**：
   - 在 `CMakeLists.txt` 中配置了 `windeployqt` 构建后自动部署指令，确保编译后自动将 Qt 运行时库同步至输出目录。

### 2. 遇到的问题与解决过程

本周在多窗口数据绑定、UI 主题适配与文件路径定位中排查并解决了多个典型工程问题：

#### 问题一：Windows 动态库环境变量优先级导致的入口点缺失（错误码 0xC0000139）
- **现象**：在 CLion 中成功通过编译，但点击运行后程序瞬间异常终止，控制台输出 `进程已结束，退出代码为 -1073741511 (0xC0000139)`。
- **定位与分析**：通过 `objdump -p` 分析 `BankManage.exe` 的导入表，发现依赖于 `Qt6Core.dll`。进一步遍历系统环境变量发现，由于本机安装了 Anaconda，其路径 `D:\Anaconda\Library\bin` 位于系统 `PATH` 最前端，导致 Windows 优先加载了 Anaconda 自带的旧版 Qt 动态库，造成符号入口严重失配。
- **解决过程**：Windows 系统的动态库加载机制规定“程序所在同级目录拥有最高搜索优先级”。因此在 `CMakeLists.txt` 中引入 `POST_BUILD` 自定义命令，调用 `${CMAKE_PREFIX_PATH}/bin/windeployqt.exe` 将 MinGW 编译器原生的 Qt 动态库（`Qt6Core.dll`、`Qt6Widgets.dll`、`platforms/qwindows.dll` 等）自动拷贝到 `cmake-build-debug/` 目录下，彻底规避了系统全局环境变量的污染。

#### 问题二：操作系统暗黑模式（Dark Mode）与硬编码样式的冲突
- **现象**：储户登录成功后，主界面顶部的客户信息文字极度昏暗发灰，肉眼几乎无法辨认。
- **定位与分析**：代码中对标签样式进行了硬编码：`color: #212529`（深灰色）。由于开发机操作系统开启了全局暗黑模式，Qt 默认采用深灰色作为窗口背景底色，深灰文字叠在深灰背景上，对比度极低。
- **解决过程**：彻底清理了界面组件中对前景文本颜色的非必要硬编码，使其自适应继承系统的调色板前景色（暗黑模式下为纯白，明亮模式下为纯黑）；同时将余额高亮色由深蓝调整为高对比度的明亮浅青蓝（`#38bdf8`），状态标签改用清新薄荷绿与珊瑚红，实现了自适应暗黑模式的高对比度美化。

#### 问题三：数据重新装载时多账户聚合绑定的丢失
- **现象**：储户在线开户后名下能看到新卡，但关闭程序重新打开后，储户名下的银行卡下拉列表全部显示为空。
- **定位与分析**：深入审查 `Storage.cpp` 的 `loadAccounts` 逻辑发现：读档时仅调用了 `bank.addAccount(...)` 将账户实例放回银行账户总表中，却遗漏了向对应的 `Customer` 对象回填 `accountId`。因此重新启动时，客户对象内部维护的卡号数组其实处于空状态。
- **解决过程**：在 `TextFileStorage::loadAccounts` 中，每解析并还原一个账户后，立即通过 `bank.findUser(ownerId)` 动态向下转型为 `Customer*`，调用 `cust->addAccount(id)` 完成双向绑定的补全，解决了读档后名下账户丢失的隐蔽 Bug。

#### 问题四：执行工作目录切换引发的存储文件定位失败
- **现象**：当直接进入 `cmake-build-debug/` 运行程序时，系统弹出“用户不存在，用户名或密码错误”，无法完成首次登录。
- **定位与分析**：程序默认以相对路径 `"data/users.txt"` 打开数据文件。当在 IDE 根目录或构建子目录不同位置启动时，当前工作目录（CWD）发生偏移，若该目录下没有预先放置 `data/` 目录，文件流打开将静默失败，内存用户表为空。
- **解决过程**：在 `Storage.cpp` 中编写了智能路径解析函数 `resolvePath`：优先检查当前目录下的 `data/`，若不存在则自动向上回溯一级（`../data/`）探测。同时在启动入口处增加保底检测，若读取后用户表为空，自动初始化默认测试数据并存盘，杜绝了初次部署时的空库报错。
