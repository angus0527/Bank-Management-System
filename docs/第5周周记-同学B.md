### 1. 本周完成

本周进入系统编码实施阶段，完成了用户权限类体系的完整设计与编码实现（`include/User.h` 与 `src/User.cpp`）：

1. **抽象基类 `User` 的封装与多态设计**：
   - 将用户的共有属性封装于基类：`id`（统一 64 位整型编号）、`name`（姓名）、`password`（混淆存储的密码）；
   - 声明虚析构函数 `virtual ~User() = default;`，保证通过基类指针安全销毁派生类对象；
   - 声明纯虚函数 `virtual std::string role() const = 0;`，将 `User` 确立为不可直接实例化的抽象类，由派生类按角色多态实现。
2. **派生类 `Customer`（普通储户）的实现**：
   - 继承自 `User`，重写 `role() override` 返回 `"Customer"`；
   - 扩展普通客户特有属性：`std::string phoneNumber`（手机号）与 `std::vector<long long> accountId`（名下持有的银行卡号动态数组）；
   - 实现了名下银行卡的动态维护方法：`addAccount`（开户时追加卡号）、`removeAccount`（销户时查找并删除卡号）、`getAccountIds`（只读获取卡号列表），建立了客户与账户实体的 1:N 聚合关联。
3. **派生类 `Admin`（系统管理员）的实现**：
   - 继承自 `User`，重写 `role() override` 返回 `"Admin"`，确立了管理员的操作权限标记。
4. **单模块单元测试验证**：
   - 编写了单模块驱动测试代码，实例化 `Customer` 与 `Admin` 对象，通过 `User*` 基类多态指针调用 `role()`、测试持卡动态增删，验证了多态调度与内存正常回收。

### 2. 遇到的问题与解决过程

#### 问题一：默认实参在头文件与源文件中重复定义报错
- **现象**：在 `User.h` 中为构造函数声明了默认参数 `bool isAlreadyObfuscated = false`，而在 `src/User.cpp` 的函数定义处同样写了 `= false`，编译报错提示 `redefinition of default argument`。
- **分析与解决**：C++ 语法规定，默认参数在同一作用域内只能声明一次。通常应保留在供外部引用的头文件声明中，源文件定义处不可重复出现默认值。移除了 `.cpp` 中的 `= false` 后编译通过。

#### 问题二：派生类构造函数的基类初始化时序
- **现象**：在编写 `Customer` 构造函数时，最初尝试在函数体内部用 `this->id = id` 赋值，发现基类的 `id` 属性被隐藏或编译报错。
- **分析与解决**：C++ 对象构造遵循“先基类后派生类”的严格顺序。基类 `User` 没有提供默认构造函数，派生类构造函数必须通过成员初始化列表（Member Initializer List）显式调用基类构造函数 `User(id, name, password, isAlreadyObfuscated)` 完成第一阶段基类初始化，随后才能初始化自身私有成员 `phoneNumber`。修改后代码逻辑严谨清晰。
