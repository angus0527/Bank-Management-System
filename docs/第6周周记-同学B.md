### 1. 本周完成

本周重点攻坚用户密码安全混淆机制与系统操作审计日志引擎（`Logger`）的研发：

1. **密码安全混淆算法落地（按位异或）**：
   - 为避免密码在内存与磁盘文件中以明文形式裸露，设计并实现了基于固定掩码 `0x5A`（90）的位异或混淆算法 `obfuscatePassword(const std::string &plain)`；
   - 深入利用位异或运算的数学自反性（$A \oplus B \oplus B = A$），实现单次异或加密、再次异或解密的对称逻辑；
   - 在 `User` 构造函数中引入 `isAlreadyObfuscated` 状态标记：首次用户注册时传入明文密码并自动混淆后保存；从磁盘文本读档时传入 `true`，直接按密文加载，彻底杜绝了读档时发生二次混淆逆转回明文的隐蔽隐患；
   - 实现 `verifyPassword`（验证明文密码是否与内部密文一致）与 `changePassword`（修改密码并自动混淆存储）。
2. **企业级操作审计日志类 `Logger` 独立封装**：
   - 在 `include/Logger.h` 与 `src/Logger.cpp` 中完成了日志引擎开发，采用全静态方法设计，便于全系统任意位置即时记录；
   - 结合 C++17 `<chrono>` 高精度时钟与 `<iomanip>` 的 `std::put_time`，格式化生成 `[YYYY-MM-DD HH:MM:SS]` 工业级时间戳；
   - 实现三大基础日志能力：`log(msg)`（追加记录一条带时间戳的日志）、`getAllLogs()`（只读获取全部历史日志行）、`clearAllLogs()`（清空系统日志文件）。

### 2. 遇到的问题与解决过程

#### 问题一：静态成员函数误用 `this` 指针报错
- **现象**：在编写 `Logger::setPath(const std::string& path)` 静态函数时，随手写了 `this->path = path;`，编译器直接报错：`'this' is unavailable for static member functions`。
- **分析与解决**：C++ 中静态成员函数属于整个类本身，而不是某个特定的对象实例，底层在调用时并不传递隐藏的 `this` 指针。将参数名修改为 `npath`，直接使用静态变量 `path = npath;` 完成赋值，消除了报错。

#### 问题二：静态成员变量缺少类外定义导致链接失败（undefined reference）
- **现象**：在头文件 `Logger.h` 中声明了 `private: static std::string path;`，在编译单文件成功后，链接可执行文件时报链接错误：`undefined reference to Logger::path`。
- **分析与解决**：类内部的 `static` 变量声明仅仅是符号声明，并不分配实际内存空间。必须在对应的实现文件 `src/Logger.cpp` 的全局作用域下显式给出其实体定义与初始值：`std::string Logger::path = "data/logs.txt";`。补全后顺利通过链接。
