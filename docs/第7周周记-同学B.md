2. **制定三表纯文本存储协议标准**：
   - 规划了基于纯文本行协议（字段使用竖线 `|` 分隔）的文件规范：
     - 用户表 `users.txt`：`U|用户ID|角色(C/A)|姓名|混淆密码|手机号`
     - 账户表 `accounts.txt`：`A|账号|类型(C)|用户ID|余额(分)|开户日期|年利率x10000|...|上次结息日`

3. **实现 `TextFileStorage` 的用户读写与多态反序列化**：
   - 编写了单行文本切分工具函数 `split(line, sep)`；
   - 编写 `saveUsers`：遍历 `bank.getUsers()`，根据运行时 `user->role()` 是 `"Admin"` 还是 `"Customer"` 动态提取手机号并序列化为单行文本写入 `users.txt`；
   - 编写 `loadUsers`：逐行解析 `users.txt`，根据角色标识字段（`"A"` 或 `"C"`）在堆上分别构造 `Admin` 或 `Customer` 实例，并通过 `std::make_unique` 注入到 `Bank` 中，实现了对象类型的正确多态还原。

### 2. 遇到的问题与解决过程

#### 问题一：文件写入时父级目录缺失导致 `std::ofstream` 静默写入失败
- **现象**：调用 `saveUsers` 后没有任何报错，程序正常退出，但在项目下完全找不到 `data/users.txt`。
- **分析与解决**：经排查发现，程序代码指定的相对路径为 `"data/users.txt"`。在 C++ 标准库规范中，`std::ofstream` 打开文件时，**若目标文件的父目录（`data/`）在磁盘物理上并不存在，流的打开将静默失败（`is_open() == false`）**，后续所有 `<<` 写入操作均直接被丢弃。引入现代 C++17 `<filesystem>` 库，在构造文件输出流前通过 `std::filesystem::path` 提取其父路径，并显式调用 `std::filesystem::create_directories()` 递归创建缺失目录，彻底解决了该缺陷。

#### 问题二：控制台打印持久化日志时的 UTF-8 / GBK 乱码
- **现象**：在测试读档并将用户信息打印到控制台时，中文姓名显示为 `寮犱笁` 等典型乱码。
- **分析与解决**：源文件和保存的文本数据均采用现代标准 UTF-8 编码，而中文 Windows 的控制台终端默认代码页为 GBK（代码页 936）。终端用 GBK 编码表去翻译 UTF-8 的字节流，造成了经典乱码。在测试主函数入口处引入 `<windows.h>`，调用 API `SetConsoleOutputCP(CP_UTF8)` 强制将终端活动输出代码页设为 UTF-8（65001），成功恢复清爽正确的汉字显示。
